# Architecture — locked decisions

These decisions are **locked**. A builder agent implements them as written. Change one only
with an explicit operator request, and record the change here with a date.

| # | Decision | Why |
|---|----------|-----|
| A1 | Python 3.12, **uv** (`pyproject.toml` + `uv.lock`), `uv_build` backend, package `brickts` under `src/brickts/`. | Already initialised in the repo; uv is the repo tool. |
| A2 | The **Brick model is the only path from a point to its data.** Query paths resolve `point → ref:hasExternalReference → ref:TimeseriesReference → ref:hasTimeseriesId + ref:storedAt → Database node → TimeseriesStore`. No CSV column name appears in any router, service, or query path. | Brick timeseries-storage pattern: <https://docs.brickschema.org/metadata/timeseries-storage.html>. |
| A3 | Timeseries ids are **opaque UUIDv5 strings**: `uuid.uuid5(uuid.NAMESPACE_URL, f"urn:openfdd:{building}:{equipment}:{source_column}")`. Generated once, frozen in the mapping CSV, and never recomputed at query time. | Stable across rebuilds. Opaque ids stop anyone from "just using the column name". |
| A4 | Storage sits behind an **async** `TimeseriesStore` **Protocol** (`async def read`, `write`, `exists`, `series_ids`, `stats`, `close`). The repo ships `SqliteTimeseriesStore` on **aiosqlite** only. FastAPI routers and services `await` store I/O; they import the Protocol only. CLI/bootstrap uses `asyncio.run` around the same async methods. | SQLite stands in for TimescaleDB, InfluxDB, or a historian without blocking the event loop. |
| A5 | SQLite is **long/narrow**: `samples(timeseries_id TEXT, ts INTEGER /*epoch s UTC*/, value REAL, PRIMARY KEY(timeseries_id, ts)) WITHOUT ROWID`, WAL mode, parameterized SQL only. One aiosqlite connection per store instance; **`asyncio.Lock`** serializes access. The wide CSV is never a query path. | TSDB-shaped. The PK is the (id, ts) index. |
| A6 | The Database node is typed `a ref:Database, brick:Database`. Neither class is defined in Brick 1.5 (bundled with `brickschema` 0.8.0). The Brick doc example uses `ref:Database`, and the operator asked for `brick:Database`. Queries match **either** type. Properties are non-normative and secret-free: `rdfs:label`, `bts:backend "sqlite"`, `bts:connectionEnv "BRICKTS_DB_PATH"`, `bts:schemaDescription`. | Doc: "Brick does not mandate what the properties are on the database instance". Connection strings and secrets live in env, never in the graph. |
| A7 | A store **registry** maps each Database node IRI to a store instance. Startup builds it from the Database nodes in the graph whose `bts:backend` has an implementation. Connection settings come from env (`BRICKTS_DB_PATH`). | Swapping to Timescale means a new store class plus a new Database node (or a new `bts:backend` value). Graph and API do not change. |
| A8 | Model sources: `model/site.ttl` holds the hand/AI-authored Site, Building, Floors, AHU, AHU parts, zones, and Database node. `model/points/*.csv` holds the AI-authored point mappings. `brickts model build` renders the committed `model/building_50.ttl`. The app loads `building_50.ttl` (seed). | Reviewable diffs. The mapping CSV is also the extension input. |
| A9 | Runtime graph = `model` (rdflib `Graph`, mutable) + `ontology` (Brick 1.5 from `brickschema`, immutable, loaded once and cached). Queries run on `union = model + ontology` (a fresh `Graph` built by concatenation). Mutations are **copy-on-write**: under a `threading.Lock`, copy the model, apply, re-validate refs, rebuild the union, and swap one `GraphState` reference. Readers never lock. | Small model and rare mutations. Readers never see a half-applied change. |
| A10 | Snapshot: model only (never the ontology), written to `BRICKTS_SNAPSHOT_PATH` with **atomic write** (temp file in the same dir, `fsync`, `os.replace`). Triggers: after a mutation (if `serialize_on_mutation`), a periodic asyncio task (if `serialize_interval_s > 0` and dirty), and lifespan shutdown. On startup, load the snapshot instead of the seed only if it exists **and** its mtime ≥ the seed mtime. | Matches the "periodically serialize" requirement. Safe on crash. |
| A11 | SPARQL endpoint is **read-only**. Parse with rdflib, then allow only `SelectQuery`, `AskQuery`, `ConstructQuery`, `DescribeQuery`. Reject updates (INSERT/DELETE/LOAD/CLEAR/DROP/CREATE/…), `SERVICE` anywhere, and `FROM`/`FROM NAMED`. Enforce a max query length, a row cap (algebra `Slice` wrap with fallback truncation), a timeout (`asyncio.wait_for`), and a concurrency semaphore. Set `rdflib.plugins.sparql.SPARQL_LOAD_GRAPHS = False`. | Safety. The UI uses the same endpoint. |
| A12 | Fault applicability uses the **open-fdd PyPI rule catalog** (`open_fdd.rules.RULES`: id, title, `required_roles`, `equipment_kinds`) plus a local **role → Brick requirement** table (`brick_class`, optional `parent_class`). A rule applies when every required role has a matching point in the equipment's part tree (subclass/equivalence-aware). | Reuses Open-FDD without hardcoding rule lists. |
| A13 | FC1 runs in the client through **`open_fdd.rules.run_rule("FC1", df, poll_seconds=300)`** (open-fdd 4.4.9). `df` has a UTC DatetimeIndex, role columns `duct-static-pressure`, `duct-static-pressure-sp`, `fan-cmd`, and `df.attrs = {"equipment_id": ..., "equipment_type": "ahu"}`. Source: `open_fdd/rules/cookbook_catalog.py::fc1`. | Verified working on 2026-10-09. Without `equipment_type`, the result is `NOT_APPLICABLE_EQUIPMENT_TYPE`. |
| A14 | No auth system. Mutation endpoints are disabled unless `BRICKTS_ALLOW_MUTATIONS=true` (403 otherwise). Docs say LAN/dev only. | Operator: no auth system, don't overbuild. |
| A15 | UI = static HTML/JS/CSS served by FastAPI at `/ui` (`/` redirects there). Plain `<textarea>` editor and inline-SVG plot. **No CDN and no Node build.** | Works offline. Lightweight. |
| A16 | Logging: stdlib `logging` with a small JSON formatter (`BRICKTS_LOG_JSON=true`) plus request-log middleware. No extra deps. | Structured logs without new services. |
| A17 | Data scope: `data/BUILDING_50/AHU_1/` and `AHU_2/` (each history CSV under 50 MB, no LFS). Source zip also has chillers/boilers/VAVs/weather; those stay out of the tutorial repo. | Two AHUs for equipment selection + fault applicability demos. |
