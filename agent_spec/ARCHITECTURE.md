# Architecture — locked decisions

These decisions are **locked**. A builder agent implements them as written. Change one only
with an explicit operator request, and record the change here with a date.

| # | Decision | Why |
|---|----------|-----|
| A1 | Python 3.12, **uv** (`pyproject.toml` + `uv.lock`), `uv_build` backend. Live package `bldgts` lives under the **current blog checkpoint** (`tool.uv.build-backend.module-root` → Part 2 `checkpoint/src`). No repo-root `src/`. Each part freezes its own app base. *(Operator 2026-10-17.)* | Blog checkpoints are the app bases; uv remains the repo tool. |
| A2 | The **Haystack application model is the only path from a point to its data.** Query paths resolve `point → ref:hasExternalReference → ref:TimeseriesReference → ref:hasTimeseriesId + ref:storedAt → Database node → TimeseriesStore`. Live taxonomy is **Project Haystack markers** (`bts:hasHaystackMarker`) plus typed metadata (`bts:hasHaystackTag`). Seed + tree + CRUD use markers/`siteRef`/`equipRef`/`spaceRef` only — **no Brick classes or Brick ontology**. Opaque timeseries refs stay (IRI namespace under Brick/ref is the storage pattern, not Brick taxonomy). *(Operator 2026-10-17: Haystack-only live app.)* | Opaque timeseries pattern retained; Haystack for smart-building IoT tags. |
| A3 | Timeseries ids are **opaque UUIDv5 strings**: `uuid.uuid5(uuid.NAMESPACE_URL, f"urn:openfdd:{building}:{equipment}:{source_column}")`. Generated once, frozen in the mapping CSV, and never recomputed at query time. | Stable across rebuilds. Opaque ids stop anyone from "just using the column name". |
| A4 | Storage sits behind an **async** `TimeseriesStore` **Protocol** (`async def read`, `write`, `exists`, `series_ids`, `stats`, `close`). The repo ships `SqliteTimeseriesStore` on **aiosqlite** only. FastAPI routers and services `await` store I/O; they import the Protocol only. CLI/bootstrap uses `asyncio.run` around the same async methods. | SQLite stands in for TimescaleDB, InfluxDB, or a historian without blocking the event loop. |
| A5 | SQLite is **long/narrow**: `samples(timeseries_id TEXT, ts INTEGER /*epoch s UTC*/, value REAL, PRIMARY KEY(timeseries_id, ts)) WITHOUT ROWID`, WAL mode, parameterized SQL only. One aiosqlite connection per store instance; **`asyncio.Lock`** serializes access. The wide CSV is never a query path. | TSDB-shaped. The PK is the (id, ts) index. |
| A6 | The Database node is typed `a ref:Database` only. Properties are non-normative and secret-free: `rdfs:label`, `bts:backend "sqlite"`, `bts:connectionEnv "BLDGTS_DB_PATH"`, `bts:schemaDescription`. No `brick:Database`. *(Operator 2026-10-17.)* | Connection strings and secrets live in env, never in the graph. |
| A7 | A store **registry** maps each Database node IRI to a store instance. Startup builds it from the Database nodes in the graph whose `bts:backend` has an implementation. Connection settings come from env (`BLDGTS_DB_PATH`). | Swapping to Timescale means a new store class plus a new Database node (or a new `bts:backend` value). Graph and API do not change. |
| A8 | Model sources: Haystack site seed (`bldgts.haystack.site_seed`) + `model/points/*.csv` (frozen timeseries ids + ofddRole). `bldgts model build` renders `model/building_50.ttl`. `model/site.ttl` is the Haystack site export for review. *(Operator 2026-10-17.)* | Reviewable diffs; CSV remains the extension input. |
| A9 | Runtime graph = `model` (rdflib `Graph`, mutable). **No Brick ontology load.** `union` is the model graph (empty ontology handle retained for API compat). Mutations are copy-on-write under a `threading.Lock`. *(Operator 2026-10-17.)* | Small model and rare mutations. |
| A10 | Snapshot: model only (never the ontology). Atomic write (`temp` + `fsync` + `os.replace`) to **`building.ttl` at the repo root** (`BLDGTS_TUTORIAL_TTL_PATH`, beginner-friendly, pushable) **and** to `BLDGTS_SNAPSHOT_PATH` under `var/` (gitignored crash copy). Triggers: after a mutation (background thread), `GET /api/model/ttl` / `POST /api/model/flush`, periodic asyncio task (if `serialize_interval_s > 0` and dirty), and lifespan shutdown. On startup, load the `var/` snapshot instead of the seed only if it exists **and** its mtime ≥ the seed mtime. | Tutorials can open/commit root `building.ttl`; `var/` stays local. |
| A11 | SPARQL endpoint is **read-only**. Parse with rdflib, then allow only `SelectQuery`, `AskQuery`, `ConstructQuery`, `DescribeQuery`. Reject updates (INSERT/DELETE/LOAD/CLEAR/DROP/CREATE/…), `SERVICE` anywhere, and `FROM`/`FROM NAMED`. Enforce a max query length, a row cap (algebra `Slice` wrap with fallback truncation), a timeout (`asyncio.wait_for`), and a concurrency semaphore. Set `rdflib.plugins.sparql.SPARQL_LOAD_GRAPHS = False`. | Safety. The UI uses the same endpoint. |
| A12 | Fault applicability uses the **open-fdd PyPI rule catalog** plus a local **role → ofddRole / owner-marker** table. A rule applies when every required role has a matching historized point under the equipment `equipRef` tree. *(Operator 2026-10-17: Haystack-only.)* | Reuses Open-FDD without Brick subclasses. |
| A13 | FC1 runs in the client through **`open_fdd.rules.run_rule("FC1", df, poll_seconds=300)`** (open-fdd 4.4.9). `df` has a UTC DatetimeIndex, role columns `duct-static-pressure`, `duct-static-pressure-sp`, `fan-cmd`, and `df.attrs = {"equipment_id": ..., "equipment_type": "ahu"}`. Source: `open_fdd/rules/cookbook_catalog.py::fc1`. | Verified working on 2026-10-09. Without `equipment_type`, the result is `NOT_APPLICABLE_EQUIPMENT_TYPE`. |
| A14 | No auth system. Mutation endpoints are disabled unless `BLDGTS_ALLOW_MUTATIONS=true` (403 otherwise). Docs say LAN/dev only. | Operator: no auth system, don't overbuild. |
| A15 | Interactive surface = Swagger `/docs` plus optional Part 2 `checkpoint/web/` Vite UI. Model tab preserves the scrollable tree and Edit locking, recursively includes floors/spaces/nested equipment and every visible point once, and exposes unattached records instead of dropping them. Left-click any entity in Edit to rename its display label and author markers plus typed Str/Ref/Number/Bool metadata. Suggestions require explicit review; no guessed sensor/history capabilities. Edit hides repeated validation noise; saved checks use a single on-demand surface. Server validation drives colors: red = required/invalid; yellow = recommendations only; green = no issues in the supported Haystack profile. History requirements are conditional on `his`. Parent checks include own and descendant issues. This profile is not full Haystack conformance. SPARQL **query** remains read-only (A11). SPARQL-only AI writes use the scoped plan/apply contract (A19), not `/api/sparql`. UI writes use revision-aware gated CRUD and preserve opaque timeseries references. SPARQL tab reports separate RDF integrity; RDF tab shows live Turtle. *(Operator 2026-10-17: deep Haystack/UX evaluation, value metadata, all-row rename, quiet Edit.)* | See Part 2 `HAYSTACK_MODELING.md` for required vs recommended rules and RDF mapping. |
| A19 | **SPARQL agent plan/apply (operator 2026-10-17).** Agents discover the parsed model only via read-only SPARQL (A11): real entity IRIs, typed `bts:hasHaystackTag` metadata, markers, ownership, revision, opaque timeseries refs. No filesystem/shell, no Turtle text search, no raw-RDF grep endpoint, no treating label similarity as a graph query (BAS fuzzy stays on the marker catalog). Portable Turtle uses rdflib parse/serialize only. **Writes:** `POST /api/agent/plan` accepts narrowly supported **ground** `INSERT DATA` / `DELETE DATA` (semicolon-separated). Allowed predicates: `rdfs:label`, `bts:hasHaystackMarker`, `bts:hasHaystackTag`, `bts:tagName`, `bts:tagKind`, `bts:tagValue`. Reject unsupported algebra, named-graph targets, `SERVICE`/`LOAD`/`CLEAR`/`DROP`/`CREATE`/`MOVE`/`COPY`/`ADD`/`FROM`/`USING`, ontology edits, identity/`rdf:type`, Database nodes, and any `ref:hasExternalReference` / `ref:hasTimeseriesId` / `ref:storedAt` change. Plan is scoped to explicit selected entity IRIs, expires (`BLDGTS_AGENT_PLAN_TTL_S`, default 600), and yields server-computed added/deleted triples, affected IRIs, base revision, before/after supported-profile issues, and a deterministic plan id+hash — never client summaries. Linked `bts:hasHaystackTag` nodes are compiled by tag **name**: inserts replace same-name tags; unedited names are preserved. `POST /api/agent/apply` requires `BLDGTS_ALLOW_MUTATIONS`, matching base revision, and the exact stored plan (tamper/expiry/scope-expansion/replay/stale → fail). Apply uses the same copy-on-write path as the UI, including equipRef→Brick ownership bridge; malformed batches roll back atomically; incomplete semantic drafts remain allowed and surface red/yellow like the tree. Do not claim full Haystack protocol/ontology compliance or hard-cancel SPARQL worker threads. | Keeps `/api/sparql` safe while giving agents a reviewable, revision-gated write path. |
| A16 | Logging: stdlib `logging` with a small JSON formatter (`BLDGTS_LOG_JSON=true`) plus request-log middleware. No extra deps. | Structured logs without new services. |
| A17 | Data scope: `data/BUILDING_50/AHU_1/` and `AHU_2/` (each history CSV under 50 MB, no LFS). Source zip also has chillers/boilers/VAVs/weather; those stay out of the tutorial repo. | Two AHUs for equipment selection + fault applicability demos. |
| A18 | Operator requested 2026-10-15: a standalone 84-day SQL/database/SPARQL course under `lessons/sql/`, with its own guarded `brickts_course` PostgreSQL/Timescale database and local or remote Docker recipe. Python is a psql/graph exercise launcher and test helper. It does not change A4/A5's application SQLite adapter or add an application endpoint. | Learn real PostgreSQL/Timescale and Open-FDD SQL safely, preserving the original tutorial and semantic-to-timeseries boundary. |
